# 해변 캠핑 요리

`moonlit_camp`의 모래밭에 마시멜로와 꼬치가 나타납니다. 재료를 클릭하면 충돌을 피해 걸어가 줍습니다. 왼쪽 위 **캠핑 요리**의 **주변 재료 찾기**도 같은 동선을 사용합니다.

**굽기**는 화로 근처까지 걸어간 뒤 시작합니다. 마시멜로는 6초, 꼬치는 9초부터 노릇해지고, 각각 12초·17초부터 탑니다. **꺼내기 → 먹기**로 마무리합니다. 탄 재료는 버릴 수 있습니다. 손에는 한 개만 들 수 있습니다. 화로를 클릭하면 요리 도구를 열고 가까이 갑니다.

## 방 공유

- `lib/camp-cooking.ts`: 상태 전이, 소유권, 거리·요청 검증, 생성·만료.
- `lib/use-camp-cooking.ts`: LiveKit reliable data로 공유합니다. 기능 지원을 알린 접속자 중 먼저 들어온 사람이 요청을 직렬화하므로 동시 줍기는 한 명만 성공합니다. 오래된 버전의 접속자가 방에 있어도 동작합니다.
- 관리 접속자가 나가면 900ms 동안 남은 접속자들의 최신 스냅샷을 모아 이어받습니다. 늦게 들어온 사람도 현재 재료·소유·굽기 상태를 받습니다.
- 브라우저나 서버에 저장하지 않습니다. 모두 나가면 사라집니다. 재료는 12초마다 생기며 바닥에는 최대 6개, 90초 후 만료됩니다. 소유 재료는 3분 후 정리됩니다.
- 상태는 참여 클라이언트가 관리합니다. 부정행위를 막는 서버 권한형 게임은 아닙니다.

## 그림과 성능

스프라이트젠 GPT 이미지 생성으로 만든 투명 소품 시트를 공식 `slice-sheet`로 분리했습니다. 256×256 PNG 여섯 장이며 별도 캐릭터 아틀라스를 추가하지 않습니다. 손에 든 소품, 굽는 소품의 색 변화와 먹기 효과를 사용하고 캐릭터는 기존 동작을 재사용합니다.

## 검증

- `node scripts/check-camp-cooking.mjs`: 동시 줍기, 중복 요청, 소유권, 거리, 익힘/태움/먹기, 오래된 클라이언트 공존, 스냅샷 누락 후 관리자 교체, 늦은 입장, 방 분리.
- `node scripts/check-room-seating.mjs`: 1,000개 생성 지점의 충돌 회피와 줍기·화로 접근 경로.
- 프로덕션 빌드와 새 모듈 ESLint 검사.
- 로컬 프로덕션 브라우저에서 찾기 → 걸어가기 → 줍기 → 화로 이동 → 노릇해짐 → 꺼내기 → 먹기 확인. 모바일 390×844에서 도구 패널이 화면 안에 들어오며, 추가 소품은 모두 256×256이고 전체 캐릭터 아틀라스 요청은 없습니다.
- 실제 다중 사용자 방 및 실물 아이폰 테스트는 수행하지 않았습니다. 통신 순서와 관리자 교체는 실제 훅을 실행하는 가상 다중 클라이언트 검사로 확인했습니다.
