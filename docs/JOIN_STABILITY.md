# 신규 입장 시 기존 모바일 접속자 부하

## 확인한 코드 경로

`ParticipantConnected`가 기존 접속자마다 `presence.wake()`를 실행했습니다. 각 접속자가 0/1.5/4/10초에 `REQUEST_SLOTS`를 보내고, 요청을 받은 모든 사람이 사진 전체를 포함한 `SYNC_SLOTS`를 방 전체에 방송했습니다. 신규 한 명이 기존 접속자들의 반복 요청과 전체 사진 전송을 연쇄적으로 일으켰습니다. 같은 시점의 실제 iOS 종료 로그는 확보하지 못했으므로, 이것이 모든 종료의 단일 원인이라고 단정하지 않습니다.

별도로 전송 한도를 UTF-8 바이트가 아닌 JavaScript 문자열 28,000자로 계산하고 있었습니다. JSON 감싸기와 한글/이모지 인코딩으로 묶음이 더 커졌습니다. LiveKit은 reliable 사용자 데이터에 15 KiB를 권고합니다: https://docs.livekit.io/transport/data/packets/

## 변경

- 다른 사람의 입장은 SDK 명단만 즉시 갱신합니다. 기존 접속자의 복귀/재연결 요청 일정을 다시 시작하지 않습니다.
- 입장자 자신의 준비된 데이터 채널에서 오는 요청에만 응답하며, SDK가 확인한 요청자에게 직접 보냅니다. 요청 본문의 닉네임으로 전송 대상을 정하지 않습니다.
- 방 공통 상태는 기존 접속자 중 한 명, 개인 캐릭터/앉기/텐트/반복 동작은 각 소유자가 응답합니다. 게시물·눈 놀이·요리 초기 동기화도 입장자에게 직접 전송합니다.
- 사진은 방 상태에서 분리합니다. 각 소유자의 사진만 직접 보내며, 동기화 재시도 시 동일 사진을 다시 보내지 않습니다. 전송 실패 시 다음 요청에서 재시도합니다. 입장자 자신의 사진 공지도 성공 후에만 완료 처리합니다.
- 모든 새 데이터 패킷은 JSON 포장을 포함해 최대 12 KiB입니다. 청크 발신자 격리, 잘못된 순서/개수/자료형 검사, 15초 만료, 발신자당 최대 2개·전체 16개 전송 및 합계 8 Mi 문자 보관 상한을 둡니다. 방 종료 시 버퍼를 비웁니다. 전송 가능한 JSON도 최대 8 Mi 문자입니다.
- 교체 중인 이전 버전의 청크는 유한한 크기 안에서 계속 읽습니다. 기존 코드의 전송 증폭까지 막으려면 기존 접속자도 새 버전으로 새로고침해야 합니다.
- iOS에서는 자동 입장 TTS 대신 짧은 효과음만 사용합니다. 효과음 노드는 재생 후 분리하며, 소리 끔/백그라운드에서는 입장 효과음을 만들지 않습니다. 대화 TTS 설정은 유지합니다.

## 검증

`scripts/check-join-stability.mjs`는 실제 페이지의 입장 응답 함수를 추출해 10명의 접속자와 신규 한 명 상황을 실행합니다. 기존 접속자에게 사진/상태/게시물 복사본이 전달되지 않는지, 공통 상태 응답자가 한 명인지, 사진 중복 전송과 요청 증폭이 없는지 확인합니다. 한글·이모지·이스케이프 문자열과 10개 동시 사진 전송, 순서가 바뀐 청크, 발신자 혼합, 비정상 크기/메모리/만료도 확인합니다.

모바일 복귀·재연결, 앉기·텐트·눈 놀이·요리 검사를 함께 실행합니다. 실물 아이폰에서 신규 입장과 동시에 종료되는 현상은 배포 후 추가 확인이 필요합니다.
