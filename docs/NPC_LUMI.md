# Lumi voice NPC

Lumi is a fixed `soft_male` avatar at normalized feet `(0.60, 0.47)`, separate from the ten speaking seats. Click the actor/nameplate or **루미 AI** to open the conversation. Each **말로 물어보기** click captures one utterance in Korean; final recognition sends the question automatically. Text input works without speech recognition. Only explicit microphone actions start recognition. Closing the dialog, receiving an NPC reply, and leaving the room stop recognition.

The browser uses `SpeechRecognition`/`webkitSpeechRecognition` when available. EXAONE is the text-only answer provider, not a speech recognizer. The initial implementation listens to the initiating user's microphone, not everyone's background conversation and not a wake word. Browser recognition availability and microphone permission remain device dependent.

`POST /api/npc` verifies a signed LiveKit room token and active participant membership, validates the request/history and applies per-instance rate limits. It sends the system prompt and up to eight recent messages to `https://api.exaone.ai/v1/chat/completions` with `k-exaone_v2.5`, `reasoning_effort: low` and `stream: false`. Both JSON and SSE responses are handled; only final content is returned, never `reasoning_content`. Replies are limited to 600 characters and use the existing TTS endpoint's NPC-specific 600-character limit.

The server broadcasts the resulting `NPC_REPLY` to the LiveKit room. Clients accept server-origin NPC packets, deduplicate by reply ID, display a bubble and play TTS with the user's output volume/mute setting. Speech animation follows audio playback. Browsers blocking autoplay show a replay control in the NPC dialog; a Korean browser-synthesis fallback covers TTS retrieval errors. The caller also receives the reply over HTTP if the broadcast arrives late. If broadcasting fails, the caller is told the reply is currently local only.

Set **EXAONE_API_KEY** as a server environment variable, locally in ignored `.env.local` and in the Vercel project's Production environment. The key is never sent to the browser or committed. Deployment uses the existing Vercel project; no persistent agent process is required for this click-to-speak design. A later always-listening or wake-word agent would be a separate addition.

Validation: `node scripts/check-npc.mjs` covers fragmented UTF-8 SSE, JSON, reasoning exclusion, malformed responses, auth/origin/history checks, room broadcasting and rate limits. `--live` additionally makes one real provider request using the local environment file. Browser QA under `sprites_run/npc-lumi-20261111` uses isolated fake recognition/audio/network responses to check voice-to-question wiring, text/history, talk animation, remote packets, unsupported-browser messaging and 390×844 layout; it does not claim a real microphone/recognition-service acoustic test. A separate real EXAONE request and real TTS audio retrieval were successful.
