# 캐릭터 비율과 수신 상호작용 수정

## 적용

- 귀여운 캐릭터는 1.0배, 검은 민소매 근육질 캐릭터는 1.20배로 표시한다. 원본을 가로나 세로로 따로 늘리지 않고 균일하게 확대한다. 발 기준점은 그대로 유지한다. `lib/sprite-v2.ts`의 `characterScale`이 방, 선택 미리보기, 캐릭터 실험실의 공통 기준이다.
- 상호작용 접근 거리는 양쪽 실제 표시 크기의 평균으로 계산한다. 후속 사용자 요청에 따라 접근 목적지 Y는 상대와 같은 발바닥 기준선으로 고정했다. 키 차이는 체형에 남기며 발 위치를 위아래로 옮겨 입 높이를 강제로 맞추지 않는다.
- 상호작용 이름 배지와 자동 설명 말풍선을 제거했다. 시스템 채팅 기록은 남긴다.
- 수신 동작은 상대 기기의 절대 시각으로 남은 재생 길이를 줄이지 않는다. 전송 대기 시간만 제한적으로 보정하고, 재생 길이는 항상 보장한다. 구버전 패킷도 전체 동작을 재생한다.
- 재생 중 채팅 반응·이동 취소용 일반 포즈가 상호작용을 덮어쓰지 못한다. 중복 ID를 무시하고 만료 타이머에 버전을 부여해 이전 타이머가 새 동작을 지우지 않게 한다. 상호작용 아틀라스를 캐릭터 등장 시 미리 디코딩한다.

## 새 캐릭터 5명 — 기본 디자인 완료 / 동작 대기

금발 태닝 남자, 여성스러운 남자, 여장 남자, 게이 남자, 베어 남자. 모두 성인이다. 베어는 큰 체격·풍성한 수염·체크 셔츠, 게이 캐릭터는 버건디 재킷과 프라이드 핀을 착용한 한 명의 디자인이며 정체성에 보편적인 외형이 있다는 뜻은 아니다.

`public/plaza/roster-v5/<id>/concept.png`에 전신 그림을 저장했고 `/character-lab#new-characters`에서 볼 수 있다. 실제 방의 선택 목록에는 모션이 완성되기 전까지 추가하지 않는다.

sprite-gen `gen --provider codex --model gpt-5.6-sol`로 베이스 5개 생성. 일부 결과는 요청한 크로마 대신 네이티브 알파로 생성되어 크로마 처리 결과가 비어 있었으므로 그 결과를 거절했다. 보존된 원본의 실제 알파를 sprite-gen `slice-sheet --chroma-key none --alpha-floor 192 --grid 1x1 --fit contain`으로 추출했다. 수작업 이미지 보정은 하지 않았다.

모든 상태의 요청·프롬프트·레이아웃 가이드는 로컬 `sprites_run/roster-v5/<id>/run`에 준비되어 있다. 각 캐릭터 24개 상태: 대기 3방향, 걷기 3방향, 말하기, 정면 점프, 상호작용 8종의 send/receive. 첫 중단 뒤 사용자 요청으로 같은 GPT 방식을 재개해 120행 중 99행이 생성됐다. 금발·여성스러운·게이·베어는 각각 20행, 여장은 19행이다. 선물·춤 20행과 여장 쓰다듬기 받기 1행은 다시 사용량 한도에 걸려 미생성 상태다. 일부 원본은 방향 검수에도 실패했다: 금발/베어의 `up_idle`이 정면이고, 여장의 `side_idle`이 정면이다. 세 행은 한도 회복 후 재제작해야 한다. 생성됐다는 사실만으로 검수 통과로 취급하지 않는다.

사용자 선택: 한도 회복 후 같은 GPT 방식으로 계속. API 과금/다른 제공자로 변경하지 않았다. 자동 재개는 설정하지 않았다. 완성 전 방 선택 목록에는 넣지 않았다. 작업 중인 선택 목록/렌더러 통합은 `sprites_run/roster-v5/integration.pending.patch`와 `character-manifests.pending.ts.txt`에 보존했다. 원본 run을 수정하거나 다른 캐릭터 동작으로 빈 프레임을 채우지 않았다.

## 겹친 캐릭터 선택 수정

`lib/sprite-hit.ts`는 각 아틀라스의 불투명 픽셀을 압축된 1비트 마스크로 저장한다. 렌더된 프레임 좌표, 좌우 반전, 캐릭터 확대율과 화면상의 크기를 반영하고 깊이 순서대로 실제 그림 픽셀을 검사한다. 투명한 자기 셀 여백은 뒤 캐릭터의 클릭을 가로채지 않는다. 이름표는 계속 직접 선택할 수 있다. 텍스처가 로딩 중이면 잘못된 전체 사각형으로 선택하지 않는다.

로컬 실제 방에서 포옹 중 상대 몸통을 클릭하는 점이 내 캐릭터 사각형 안에도 들어가는 상황을 검사했다. 상대 메뉴가 열렸고 내 메뉴는 열리지 않았다. 두 배우의 발 Y는 모두 60%로 일치했다.

## 검증

- `node scripts/check-social-playback.mjs`: 기기 시각 ±10초, 전송 지연 0~2.5초의 35조합, 구버전 패킷, 덮어쓰기 방지, 체격별 접점 계산 통과.
- 로컬 방의 실제 수신 함수에 mock 패킷을 주입: 포옹·펀치·춤을 상대가 시작하고 중복 패킷, 일반 포즈, 중지 이벤트를 섞어도 양쪽 전체 프레임이 끝까지 공통 박자로 재생됨. 머리 위 배지 0개, 상호작용 설명 말풍선 없음.
- 기존 경로·충돌 검사와 152프레임 에셋 검사, TypeScript 및 변경된 독립 모듈 ESLint 확인.
- `node scripts/check-sprite-hit.mjs`: 투명 여백, 앞 캐릭터 몸체, 좌우 반전, 깊이·동일 깊이 그리기 순서, 영역 밖 클릭 검사 통과.
- 새 그림 5개 실제 브라우저 디코딩과 비율 미리보기 확인. 실제 통화 환경의 별도 기기 검증은 수행하지 않았다.
