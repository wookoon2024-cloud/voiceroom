# 캐릭터 비율과 수신 상호작용 수정

## 적용

- 귀여운 캐릭터와 검은 민소매 근육질 캐릭터의 기본 배율은 1.0과 1.20이다. 아래 공통 확대율을 곱해 표시한다. 원본을 가로나 세로로 따로 늘리지 않고 균일하게 확대한다. 발 기준점은 그대로 유지한다. `lib/sprite-v2.ts`의 `characterScale`이 방, 선택 미리보기, 캐릭터 실험실의 공통 기준이다.
- 상호작용 접근 거리는 양쪽 실제 표시 크기의 평균으로 계산한다. 후속 사용자 요청에 따라 접근 목적지 Y는 상대와 같은 발바닥 기준선으로 고정했다. 키 차이는 체형에 남기며 발 위치를 위아래로 옮겨 입 높이를 강제로 맞추지 않는다.
- 상호작용 이름 배지와 자동 설명 말풍선을 제거했다. 시스템 채팅 기록은 남긴다.
- 수신 동작은 상대 기기의 절대 시각으로 남은 재생 길이를 줄이지 않는다. 전송 대기 시간만 제한적으로 보정하고, 재생 길이는 항상 보장한다. 구버전 패킷도 전체 동작을 재생한다.
- 재생 중 채팅 반응·이동 취소용 일반 포즈가 상호작용을 덮어쓰지 못한다. 중복 ID를 무시하고 만료 타이머에 버전을 부여해 이전 타이머가 새 동작을 지우지 않게 한다. 상호작용 아틀라스를 캐릭터 등장 시 미리 디코딩한다.

## 새 캐릭터 5명 — 동작 완료 / 선택 가능

금발 태닝 남자, 여성스러운 남자, 여장 남자, 게이 남자, 베어 남자. 모두 성인이다. 베어는 큰 체격·풍성한 수염·체크 셔츠, 게이 캐릭터는 버건디 재킷과 프라이드 핀을 착용한 한 명의 디자인이며 정체성에 보편적인 외형이 있다는 뜻은 아니다.

`public/plaza/roster-v5/<id>/`에 전신 그림, 실제 투명 아틀라스, 런타임 manifest를 저장했다. 방의 캐릭터 선택창과 `/character-lab`에서 모두 선택할 수 있다. 기존 두 명과 합쳐 총 7명이며 정규 ID를 저장·전송·수신한다. 기존 ID 마이그레이션도 유지했다.

sprite-gen `gen --provider codex --model gpt-5.6-sol`로 베이스 5개 생성. 일부 결과는 요청한 크로마 대신 네이티브 알파로 생성되어 크로마 처리 결과가 비어 있었으므로 그 결과를 거절했다. 보존된 원본의 실제 알파를 sprite-gen `slice-sheet --chroma-key none --alpha-floor 192 --grid 1x1 --fit contain`으로 추출했다. 수작업 이미지 보정은 하지 않았다.

각 캐릭터 24개 상태: 대기 3방향, 걷기 3방향, 말하기, 정면 점프, 상호작용 8종의 send/receive. 총 120행·620프레임이다. 중단됐던 선물·춤과 쓰다듬기 받기 21행을 같은 GPT 구독 방식으로 완성했다. 방향 오류가 있었던 금발/베어의 `up_idle`, 여장의 `side_idle`도 다시 생성해 올바른 뒷모습/오른쪽 모습을 확인했다. API 과금이나 제공자 변경, 다른 캐릭터 프레임 대체는 없다.

sprite-gen의 정식 `extract → compose-atlas → preview_animation → inspect`로 제작했다. 각 캐릭터의 원본·거절된 방향 그림·요청·프롬프트·레이아웃 가이드·검수 시트는 로컬 `sprites_run/roster-v5/<id>/run`에 보존한다. QA용 보드는 원본 프레임을 배치한 것으로 게임 에셋을 수작업 보정하지 않는다.

머리 크기를 비교해 캐릭터별 기본 배율을 귀여운 1.0, 근육질 1.20, 금발 태닝 1.35, 여성스러운 1.32, 여장 1.34, 게이 1.36, 베어 1.20으로 보정했다. 여기에 공통 표시 배율 1.12를 적용해 전체를 12% 확대했다. 렌더러·선택창·미리보기·상호작용 접근 거리가 같은 `characterScale`을 사용한다. 원본 종횡비와 각자 고유 체형을 유지하며, 192×240 셀 규격과 발 기준선은 공통이지만 키를 같게 강제하지 않는다.

캐릭터·화면 선택창은 최대 너비 376px의 4열 목록으로 정리했다. 캐릭터 7명을 2행에 표시하고, 화면 모드는 상단의 두 버튼으로 전환한다. 선택된 캐릭터는 체크 표시와 강조색으로 구분한다. 320×640 화면에서도 296×387px 안에 모든 항목과 완료 버튼이 들어가며 가로 넘침이 없다. 실제 로컬 방에서 7명 선택·표시 배율, 모드 전환과 Escape 닫기를 확인했다.

대기 동작 일부는 의도적으로 미세한 호흡/깜박임만 있어 엔진의 일반 움직임 임계치 경고가 있다(금발 오른쪽/뒤, 여성스러운 정면/오른쪽, 게이 3방향, 여장 정면/오른쪽). 실제 프레임은 서로 다르며 대기 동작으로 검토했다. 걷기·점프·상호작용을 정지 프레임으로 대체하지 않았다. 선물은 장식용 동작으로 아이템을 영구 보관하지 않는다.

## 겹친 캐릭터 선택 수정

`lib/sprite-hit.ts`는 각 아틀라스의 불투명 픽셀을 압축된 1비트 마스크로 저장한다. 렌더된 프레임 좌표, 좌우 반전, 캐릭터 확대율과 화면상의 크기를 반영하고 깊이 순서대로 실제 그림 픽셀을 검사한다. 투명한 자기 셀 여백은 뒤 캐릭터의 클릭을 가로채지 않는다. 이름표는 계속 직접 선택할 수 있다. 텍스처가 로딩 중이면 잘못된 전체 사각형으로 선택하지 않는다.

로컬 실제 방에서 포옹 중 상대 몸통을 클릭하는 점이 내 캐릭터 사각형 안에도 들어가는 상황을 검사했다. 상대 메뉴가 열렸고 내 메뉴는 열리지 않았다. 두 배우의 발 Y는 모두 60%로 일치했다.

## 검증

- `node scripts/check-social-playback.mjs`: 기기 시각 ±10초, 전송 지연 0~2.5초의 35조합, 구버전 패킷, 덮어쓰기 방지, 체격별 접점 계산 통과.
- 로컬 방의 실제 수신 함수에 mock 패킷을 주입: 포옹·펀치·춤을 상대가 시작하고 중복 패킷, 일반 포즈, 중지 이벤트를 섞어도 양쪽 전체 프레임이 끝까지 공통 박자로 재생됨. 머리 위 배지 0개, 상호작용 설명 말풍선 없음.
- 기존 경로·충돌 검사와 152프레임 에셋 검사, TypeScript 및 변경된 독립 모듈 ESLint 확인.
- `node scripts/check-character-roster.mjs`: 7명 ID/개별 배율, 모든 이동 상태, 8종 상호작용의 양쪽 역할·전체 재생 시간, PNG와 atlas 좌표 검증. 49개 캐릭터 조합이 동일한 상태 규격을 공유한다.
- 새 캐릭터 5명 모두 실제 로컬 방 메뉴에서 선택·표시·텍스처 디코딩을 확인했다. 각 124프레임, 총 620프레임에서 빈 프레임·셀 끝 잘림이 없고 각 상태에 서로 다른 그림이 있음을 확인했다.
- 새 선물/춤의 5명 × 보내기/받기 × 2동작, 총 20개 실제 방 렌더링 사례를 검사해 공통 프레임 시각과 종료를 확인했다. 상호작용 이름 배지는 모두 0개였다. 최초 텍스처 준비 중 금발 선물 보내기 1프레임이 관측 샘플에서 빠져, 로드 후 별도로 재확인했다.
- `node scripts/check-sprite-hit.mjs`: 투명 여백, 앞 캐릭터 몸체, 좌우 반전, 깊이·동일 깊이 그리기 순서, 영역 밖 클릭 검사 통과.
- 새 그림 5개 실제 브라우저 디코딩과 비율 미리보기 확인. 실제 통화 환경의 별도 기기 검증은 수행하지 않았다.
