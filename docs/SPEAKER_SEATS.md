# 발화석 충돌 처리

발화석은 `lib/speaker-seats.ts`의 착석 요청 목록으로 계산한다. 화면마다 자신의 자리 요청을 방어하거나 충돌 때마다 새 요청을 만들어 보내지 않는다.

- 사용자마다 희망 자리, 변경 버전, 요청 우선순위를 하나만 유지한다.
- 모든 참여자는 같은 우선순위(요청 시각, 같으면 닉네임 코드 순서)로 배정한다. 서버의 실제 클릭 시각을 판정하는 방식은 아니다.
- 요청 자리를 먼저 배정하고, 충돌한 요청은 남은 빈자리에 배정한다. 최대 10자리이며 한 사람에게 한 자리만 부여한다.
- 만석인 경우 자기 요청을 해제하고 대기·음소거로 전환한다.
- `TAKE_SLOT`, `LEAVE_SLOT`, `UNSEAT_USER`에는 변경 버전을 포함한다. `SYNC_SLOTS`, `RENAME`에는 요청 목록도 포함한다.
- 퇴석 기록도 유지하여 늦게 온 착석/스냅샷이 이전 상태를 되살리지 못하게 한다.
- 재접속 시 요청/스냅샷을 다시 공유한다. 이전 방의 접속 후 타이머는 새 방에서 실행하지 않는다.
- React 상태 반영을 기다리지 않고 슬롯 ref를 즉시 갱신해 연속 클릭·연속 패킷이 같은 빈 상태를 읽지 않도록 한다.

서버 저장소는 추가하지 않았다. 패킷이 도착하기 전에는 낙관적으로 자신이 착석한 것으로 보일 수 있지만, 같은 요청 목록을 받은 새 클라이언트들은 동일한 배정으로 수렴한다. 기존 버전의 열린 탭은 새로고침해야 이 규칙을 사용한다.

검증: `node scripts/check-speaker-seats.mjs` — 250가지 서로 다른 패킷 순서, 동시 요청, 만석, 복원, 늦은 입장, 중복 패킷, 이전 퇴석/스냅샷, 잘못된 슬롯. 실제 음성방의 참가자를 대상으로 강제 새로고침하거나 마이크 시험을 실행하지 않았다.

## 뒷사선 앉기 그림 보정

귀여운 남자 캐릭터의 `diagonal_back_sit`를 기존 GPT 이미지 행 방식으로 다시 생성했다. 앞사선 원본은 유지했다. 결과는 `public/plaza/diagonal-seating-v2/cute_male_v2/`에 저장했다.

생성 요청 및 원본·GIF는 `sprites_run/diagonal-seat-legfix-v2/cute_male_v2/`에 있다. 두 무릎, 정강이, 발목과 신발의 연결을 명시한 프롬프트로 네 프레임을 다시 생성하고 표준 extract/compose-atlas/compose-gif/inspect를 실행했다. 검사기의 작은 동작량 경고는 앉은 상태의 미세한 호흡 루프에 관한 것으로, 동작 속도나 프레임을 임의로 바꾸지 않았다.

새 그림의 골반 접점은 매니페스트의 `seat_anchors`에서 지정한다. 전신 배율을 바꾸지 않고 좌판 접점만 맞춘다. 로컬 화면에서 의자 착석 및 뒤왼쪽/뒤오른쪽 전환을 확인했다.
