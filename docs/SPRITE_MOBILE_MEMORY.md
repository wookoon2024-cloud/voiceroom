# Mobile sprite memory

The previous renderer eagerly decoded every base/social/rest/floor/back/diagonal atlas for every appearing character, even when only idle was visible. Hit testing then allocated a full-size Canvas and RGBA ImageData for each atlas. The largest sheet is 1536×5760: 33.75 MiB decoded, before the additional canvas/pixel copies. Concurrent preload across several character types can produce a large memory spike. This is a confirmed implementation risk; an actual iPhone crash report was not captured, so it is not proof of the sole cause of the reported disconnects.

`build-sprite-rows.mjs` losslessly packages the existing source motion rows into 372 small PNGs across 62 source sets, including the Santa costume. It changes no anatomy, frame geometry, timing or animation. Original manifest rectangles are translated by the packaged row's source offset. The largest runtime texture is 2.109375 MiB decoded, sixteen times smaller than the largest original atlas. Only the current row is requested; unused rest/action packs are no longer preloaded.

The build also writes `.png.hit.bin` files: a 16-byte `VRHM` / version / width / height header and one alpha bit per pixel (threshold 48). The browser fetches these directly for overlapping-character selection. It does not decode images or allocate Canvas/ImageData for hit tests. The LRU mask cache is limited to 2 MiB and 48 entries. Binary dimensions/size/version are validated, failed loads stay non-selectable until a subsequent click retries, and concurrent loads are deduplicated.

IP-only automatic session/nickname restoration was also removed. A network IP is not proof of ownership of a browser session; multiple devices sharing one address must not auto-adopt another participant's nickname. Existing browser-local session and explicit joined URLs still restore normally. The legacy session endpoint is now read only for the client's IP display, without adopting its returned nickname/session.

Validation: row pixels match the original atlas crops byte-for-byte; binary hit masks match original alpha; the 385-case sprite painting regression retains facing, frame timing/contact holds, support scales and WebKit-safe overflow/filter placement. Hit tests cover overlap, flip, depth, malformed/missing binary files, deduplication and cache eviction, with Image/Canvas constructors set to throw if used. The browser loaded only `/rows/` sprite textures and binary masks, with zero full-atlas image requests. Physical iPhone memory/crash behavior still requires observing the released version on affected devices.
